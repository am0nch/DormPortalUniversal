Getting Started
index.html · All modules
▾ System Overview

The Dormitory Administration system is a browser-based application — no internet connection, no server, and no login required after the files are opened. All data is saved automatically to your browser's local storage and can be exported as a JSON backup file.

🔒 Data Storage

Data is saved in your browser's localStorage — it persists across browser restarts but is tied to the specific browser and computer. Always export a backup before clearing browser data or switching computers.

📂 File Structure

The system consists of index.html (the menu), dorm-db.js (shared data API), and individual module HTML files inside the modules/ folder. Keep all files in the same folder.

ℹ️All modules share the same data layer (dorm-db.js). Changes made in one module are instantly visible in all others — even in other browser tabs via BroadcastChannel sync.
▾ First Launch
  1. Open index.html in a modern web browser (Chrome or Edge recommended).
  2. When prompted for your name, enter it — this is shown as the current user and stamped on every save.
  3. Select your dorm from the 🏢 Dorm dropdown (top-right of the menu). Choose "Other" to type a custom name.
  4. Click any module card to open it. All modules share the same data.
💡Tip: Keep the index.html tab open while working in module tabs — it updates live as data changes and shows at-a-glance stats for all modules.
▾ Backup & Restore

Use the buttons in the menu footer to protect your data:

  • 💾 Export All Data — Downloads a .json file containing all module data (rooms, profiles, keys, inspections, inventory, history, and photos). Store this on a USB drive or cloud backup.
  • 📂 Restore Backup — Imports a previously exported .json file. This overwrites all current data.
⚠️Important: localStorage is browser-specific. If you switch to a different browser or computer, use Export/Restore to transfer your data. Export at least once a week — or after any significant data entry session.

▾ Dorm Setup

On first use, click 🏗️ Generate Dorm Setup to create the room list. Enter room numbers manually or use a range format (e.g., 101AC-106AC, 201AC-227AC). Rooms with the suffix AC are auto-flagged as air-conditioned.

The Max Occupants dropdown (top-right of the toolbar) sets how many bed slots appear per room: 1–4. Default is 2.

ℹ️Elijah Hall default layout: Floors 1–2 (101AC–106AC, 201AC–227AC), Floors 3–4 (301AC–327AC, 401AC–427AC). All rooms default to 2 beds.
▾ Move-Out Types & Clearance

Set a reason in the 🚪 Move Out column to start the departure process. The 📋 Clearance button appears automatically in the last column.

Move-Out ReasonDescriptionSub-type
GraduatingStudent completing their program. Full clearance + fee assessment.—
Off CampusStudent leaving campusGoing Home (temp) or Leaving Dorm (permanent)
InternshipAway for internship placement—

The 📋 Clearance Modal captures:

  • Student ID, Mobile, Email, Leave Date, Form No.
  • Meter readings: Electricity IN/OUT, Hot Water IN/OUT
  • Fees: Moving, Cleaning, Key, Drawer, Chair, Stool, Other (with auto-fill from Room Inspection)
  • Destination dorm/room (for transfers)

Clicking Archive & Vacate moves the student to Room History, clears their bed slot, and the record appears in the Archive tab of Reports.

💡If a move-out Room Inspection exists for this student's room, the "Other Fee" field is auto-populated with the total damage charges — no double entry needed.
▾ Room Hold (Paid Absence)

A Room Hold lets a student keep their room while temporarily absent (going home for summer/semester break) by paying a hold fee. The room is blocked from new reservations.

  1. Check ☀️ Summer or 📖 1st Sem for the student — the Hold checkbox activates.
  2. Check the 🏠 Hold checkbox. The room badge turns Amber.
  3. Click the 💳 button to open the Hold Payment modal. Record payment method (Cash or QR) and amount paid.
ℹ️A room on hold shows "🏠 Room Held (away)" in the Status column and blocks new reservations — behaves like a solo lock. Outstanding hold payments appear in the Fee Collection report.
▾ Away Students Panel

The Away Students panel (🏃 button in the toolbar) stores student records that have been temporarily moved out without being permanently archived. Their bed is released but all data is preserved.

  • Click Mark Away from the student's row options to move them to the Away panel.
  • When they return, click ↩️ Restore and choose the room to place them back into a bed slot.
  • Away students with storage or hold payments appear in the Fee Collection report.
▾ Incoming Queue

The Incoming Queue panel (🚶 button) manages pre-reservations — students who will move in but don't have a confirmed room yet.

  1. Click + Add Incoming and fill in: Name, Student Type, Target Room, Expected Move-In Date, Transfer From (if applicable), and Notes.
  2. Once a room becomes available, click ✅ Confirm to Room on the queue entry to place the student in a bed slot directly.
  3. To remove a queue entry, click ✕ Remove.

The queue count badge updates live on the Room Reservations card in the main menu.

▾ Storage Rental

Click 📦 Manage in the Storage column to open the Storage modal for a student. You can track up to 3 storage boxes, each with a color label and box number. Payment method (Cash / QR / Not Paid) and total amount are also recorded.

Unpaid storage rentals appear in the Fee Collection report under Reports → 💰 Fee Collection.

▾ Transfer In

To record a student transferring from another dorm, click the 🔀 badge (visible when a name is entered) to open the Transfer In modal. Record: source dorm, source room number, transfer date, and notes. A Transfer In badge appears on the name cell afterward.

▾ Room Side Assignment (A / B)

Each student can be assigned to Side A (door-side) or Side B (balcony-side) of the room. Click the small side badge (🅰/🅱) next to the student's name to cycle through A → B → (unset). This assignment is used by the Room Inspection module to link move-in and move-out records to the correct bed side.

▾ Saving & Loading Data
  • Auto-save: Every change is immediately saved to localStorage. The status bar shows the last save time and current localStorage usage.
  • 💾 Save Excel: Exports all room data to an .xlsx file with three sheets: DormData, IncomingQueue, RoomHistory.
  • 📂 Load File: Import a previously saved .xlsx file to restore room data.
  • Undo / Redo: Buttons in the toolbar, or Ctrl+Z / Ctrl+Y.
⚠️Loading from an Excel file overwrites all current room data. Always export a backup before loading.

Student Profiles
modules/student-profiles.html
Ready
▾ Overview

The Student Profiles module is the central student directory. It stores full personal, academic, and emergency contact information. A completeness score (0–100%) tracks how much of each profile is filled in, based on 13 key fields.

Profiles are linked to Room Reservations via Student ID. Once a student has both a profile and a reservation with matching IDs, a 👤 Profile badge appears on their name in the reservations table.

▾ Creating & Editing Profiles
  1. Click + Add Profile to open the edit modal.
  2. Fill in: First Name, Surname, Student ID, Course, Year, Nationality, Birth Date, Cell Phone, Email, Home Address, Father's Name, Mother's Name, Emergency Contact Name & Phone, Blood Type.
  3. Optionally upload a profile photo (JPEG/PNG). Photos are auto-compressed to ~25–50 KB to save space.
  4. Click Save. The profile appears in the list with a completeness percentage badge.
💡Completeness score is based on 13 fields: First Name, Surname, Student ID, Cell Phone, Email, Birth Date, Nationality, Home Address, Father's Name, Mother's Name, Emergency Name, Emergency Phone, and Blood Type. A profile at ≥90% is counted as "Complete."
▾ Importing Profiles

📥 Import Registrar Excel

Imports an Excel file from the Registrar's office. Creates stub profiles with available columns (name, ID, course, year, etc.). Profiles matched by Student ID are not overwritten — safe to run repeatedly.

📋 Import MS Forms CSV

Imports a CSV exported from a Microsoft Forms survey. Flexible header matching — columns like "Full Name", "Student No.", "Emergency Contact" are auto-detected. Updates matching profiles in-place.

Recommended workflow:

  1. Import from Registrar Excel → creates stub profiles for all enrolled students.
  2. Share a Microsoft Forms link for students to fill in their own personal details.
  3. Export the Forms responses as CSV, then import via "Import MS Forms CSV".
  4. Review completeness scores and print A4 cards for complete profiles.
▾ Printing Profile Cards

Click 🖨️ Print Card on any profile to open a printable A4 portrait card (Style B two-column layout). The card includes the student photo (if uploaded), all profile fields in two columns, and the current room assignment pulled from Room Reservations (matched by Student ID).

These cards are suitable for filing in the dorm's physical student binder or posting on the resident bulletin board.

▾ Exporting Profile Data

Click 📤 Export Excel to download all profiles as an .xlsx file with 47 columns — all fields including room assignment (pulled from Room Reservations via Student ID match). Suitable for sending to the Registrar or Finance office.

▾ Reading the Room Grid

The Floor Plan shows all rooms as color-coded tiles. Use the floor filter buttons at the top to view one floor at a time, or see all floors at once. Hover over a room tile to see a tooltip with occupant names and Student IDs.

Tile ColorMeaning
GreenAvailable — at least one empty bed slot, no lock
YellowLeaving Soon — all slots filled but ≥1 student has a leave date set
AmberRoom Hold — a student is paying to hold the room while away
RedFull — all slots occupied, no one leaving; or Solo Lock
💡The ❄️ badge on a room tile marks it as an AC room. The grey text below each occupant name is their Student ID (if one is saved).
▾ Bathroom Pairing Configuration

Bathroom pairing groups rooms that share a hot water bathroom. This configuration is used by the Electricity & Hot Water module to group students for hot water bill splitting.

  1. Click ⚙️ Configure Bathroom Pairing.
  2. Select the rooms that share a bathroom (e.g., 301AC + 302AC share one bathroom).
  3. Click + Add Pair. Repeat for all bathroom groups on all floors.
  4. Click Save Pairing. The configuration is stored immediately.
▾ Printing the Floor Plan

Click 🖨️ Print Floor Plan to open an A4 landscape print window showing all floor tiles with occupancy colors and room numbers. Useful for posting on the dorm notice board or sharing with administration.

Electricity & Hot Water
modules/utilities.html
Ready
▾ Electricity Tab

Records monthly electricity meter readings per room and calculates the per-student bill.

  1. Select or create a billing period (e.g., "May 2026") using the period selector.
  2. Enter the Previous Reading and Current Reading for each room's electricity meter.
  3. Enter the Rate per kWh in the rate field.
  4. The module auto-calculates usage (kWh), total cost, and splits the bill equally among all current room occupants.
▾ Hot Water Tab

Hot water billing is based on the bathroom pairing groups configured in the Floor Plan module. All students sharing a bathroom split the hot water bill equally.

  1. Select the billing period (same one used for electricity).
  2. For each bathroom group, enter previous and current hot water meter readings.
  3. Enter the rate per unit.
  4. The module groups students by bathroom pair and calculates each person's share automatically.
ℹ️Rooms with the "AC" suffix (e.g., 426AC) are automatically matched to their non-suffix equivalent (426) for billing. No manual adjustment needed for AC room naming.
▾ Summary Tab & Export

The Summary tab shows a combined per-student bill (electricity + hot water) for the selected billing period, including Student IDs for easy reference. Click 📤 Export Excel to download the full billing table as a .xlsx file for distribution or Finance submission.

Reports
modules/reports.html
Ready

The Reports module has 8 tabs covering all major report types. All output is print or PDF — no data is entered here. The module is read-only and intentionally lightweight.

▾ 📁 Archive Tab

Shows all students who have been vacated and archived — Graduating, Off Campus, and Internship departures. Displays clearance form completion status, fees collected, meter readings, and contact info. Filterable by floor, searchable by name. Click 🖨️ Print Archive for an A4 report.

▾ 🛏️ Room Report Tab

Shows the current occupancy snapshot for all rooms: student name, Student ID, move-out reason, solo/storage/hold status, and keys returned. Sorted by room number. Includes an ID column for cross-referencing with Registrar records. Printable as A4.

▾ 📋 Custom Report Tab

Build a flexible columnar report by checking which fields to include: Name, Room, Student ID, Move Out Reason, Summer, 1st Sem, Leave Date, Return Date, Storage Rental, Solo, Hold Status, Keys Returned. Filter by floor. Click Generate Report then 🖨️ Print.

▾ 🔀 Pivot Tab

Shows a summary count of students grouped by Move Out Reason and Off Campus Type. At a glance: how many are graduating, leaving the dorm, going home, or on internship. Printable as A4 landscape.

▾ 🏠 Holds Report Tab

Lists all currently active room holds: student name, room, payment method, and amount paid. Useful for reconciling hold payments with the Finance Office. Printable as A4.

▾ 📦 Storage Report Tab

Lists all storage rentals — both active students and away students — with box numbers, colors, payment status, and total amounts. Distinguishes paid vs. unpaid. Printable as A4.

▾ 📋 Clearance Tab

This tab has two sections:

  • Section A — Overview: All students with a move-out reason in one table. Shows clearance form completion status, leave date, and total fees assessed.
  • Section B — Form Builder: Select a room and occupant (or "Both occupants" or "Blank form") to generate a printable landscape A4 Finance Office clearance form. If a Room Inspection exists for that student, damage charges are auto-filled.
💡Selecting "Both occupants" generates two clearance sheets with a page-break between them — print both sides of a shared room in one click.
▾ 💰 Fee Collection Tab

Aggregates all outstanding payments across the system into one view. Five summary stat cards show totals. The detail table lists every unpaid item:

  • Storage rentals marked "Not Paid" (active and away students)
  • Room holds marked "Not Paid"
  • Pending clearance forms (not yet completed/submitted)
  • Lost key fines not yet collected

Click 🖨️ Print Fee Report to generate an A4 summary for Finance.

Key Inventory
modules/key-inventory.html
Ready
▾ Initial Setup

Before using the module, click the ⚙️ Settings tab to configure:

  • Cash Fine Amount — penalty for a lost key paid in cash
  • Account Deduction Amount — penalty charged to the student account
  • Student Return Time Limit — minutes before a student key is overdue
  • Worker Return Time Limit — hours before a worker key is overdue
  • Semester Label — e.g., "2nd Semester 2025–2026" (appears on print sheets)

Then click 🔑 Generate from Rooms (in the Inventory tab toolbar) to auto-create A and B key records for every room currently in the reservation list.

▾ Checking Out & Returning Keys
  1. Go to the Active tab or Inventory tab and find the key by room number.
  2. Click ✅ Check Out. Enter borrower name, borrower type (Student / Worker / Staff / Guest), and expected return time.
  3. The key status changes to Checked Out. It appears in the Active tab.
  4. When the key is returned, click ↩️ Return on its Active tab entry. The return is logged in the key's history.

The system checks for overdue keys automatically every 60 seconds and updates status to Overdue when the return time has passed.

▾ Recording a Lost Key
  1. Find the key in the Active tab (it may already be Overdue).
  2. Click ❌ Mark Lost. The Fine modal opens automatically.
  3. Choose the resolution: Cash (fine collected in person), Account (deducted from student account), or Waived (no charge).
  4. The key status updates to Lost. If the fine is not yet paid, it appears in the Fee Collection report.
▾ Print: Shift Sheet, Ledger & Agreement
  • 🖨️ Print Shift Sheet (toolbar button) — A4 sheet listing all currently checked-out keys: room, key type, borrower name, checkout time, due time. Use for handover between duty shifts.
  • 🖨️ Print Ledger (toolbar button) — 2-page A4 Master Borrower Agreement Signature Ledger (48 rows total) for manual sign-in by each borrower. Includes dorm name and fine amounts from Settings.
  • 📄 Agreement tab — On-screen preview of the Borrower Rules & Responsibilities Agreement. Click 🖨️ Print Agreement for a printed copy to give each new borrower. All values are dynamic (dorm name, time limits, fine amounts).

Room Inspection
modules/room-inspection.html
Ready
▾ Creating a New Inspection
  1. Click + New Inspection in the toolbar.
  2. Select the Room from the dropdown (populated from Room Reservations).
  3. Choose Inspection Type: Move-In or Move-Out.
  4. Set the Inspection Date and Semester label.
  5. Assign students to Side A (door-side) and Side B (balcony-side) using the dropdowns. The system prevents two students from being assigned the same side.
  6. Click Start Inspection to open the full checklist.
▾ Filling in the Checklist

The checklist is divided into four sections:

SectionItems CoveredCost Split
Side A (Door)Student A's personal area: bed, mattress, desk, chair, wardrobe, drawers, bookshelf, stool, windowCharged to Student A
Side B (Balcony)Student B's personal area — same item listCharged to Student B
Shared FixturesCeiling fan, curtains, door lock, room sign, floor, light fixturesSplit between both students
BathroomToilet, shower head, mirror, water heater, tiles, floor drainSplit between both students

For each item, select a condition:

  • Good — No action needed
  • Fair — Minor wear, no charge
  • Poor — Needs repair, partial charge applies
  • Damaged — Full replacement cost charged
  • N/A — Item not present in this room (e.g., AC unit in non-AC room)
ℹ️AC Unit items default to N/A for non-AC rooms automatically. Conditions are graded against the paired Move-In record for Move-Out inspections.
▾ Charge Calculation & Edit Charges

For Move-Out inspections, the system compares current conditions against the paired Move-In record. Deteriorated items trigger a repair/replacement charge based on default costs set in Settings.

After saving the inspection, click ✏️ Edit Charges to adjust any repair amount. This is useful when actual repair costs differ from the defaults.

The Charges tab shows a per-student summary of all charges from saved inspections.

💡When you open a student's clearance form in Room Reservations (or the Clearance tab in Reports), damage charges from the Room Inspection are automatically pre-filled in the "Other Fee" field — no double entry needed.
▾ Printing Inspection Documents
  • 🖨️ Print Inspection Sheet — A4 portrait checklist with all items, conditions per section, charge amounts, and signature lines for both students and the inspector. Suitable for filing.
  • 🖨️ Print Cost Card — A5 cost summary card listing all charged items and per-student amounts. Designed to be posted inside the room door or given to students at check-out.
▾ Settings Tab

The Settings tab lets you set the default replacement/repair cost for each item type (bed frame, mattress, desk, etc.) and the current semester label. These costs are used when auto-calculating damage charges.

Click ↺ Reset to Code Defaults to restore the built-in price list if your customized costs need to be reverted.

Inventory
modules/inventory.html
Ready
▾ Overview

The Inventory module tracks every physical asset in the dorm — furniture, appliances, fixtures, and supplies — across all student rooms and common areas. Each item has a unique barcode ID that can be printed and physically attached to the item.

📍 Locations Tracked

  • All student rooms (from Room Reservations)
  • Lobby · Worship Hall · Dean's Office
  • Electricity Rooms F1–F4
  • Storage Rooms F2–F4
  • Corridors F1–F4
  • Laundry Room · Recreation Room
  • Guard Post · Common Kitchen · Sick Bay
  • + any custom locations you add in Settings

🏷️ Barcode System

Each item gets a unique ID in the format INV-XXXXXXXX. Code 39 barcodes are generated entirely in-browser (no internet needed) and are compatible with any standard USB barcode scanner.

Scanning the barcode reads the item ID as keyboard input — you can search by ID in the Items tab.

▾ Quick Start — Seed All Rooms
  1. Go to the ⚙️ Settings tab and review the room template. The default includes: Bed Frame ×2, Mattress ×2, Study Desk ×2, Chair ×2, Wardrobe ×2, Drawer Unit ×2, Bookshelf ×1, Stool ×2, Ceiling Fan ×1, Curtain Set ×1, Door Lock Set ×1, Room Number Sign ×1, Trash Bin ×1, and Air Conditioner Unit ×1 (AC rooms only).
  2. Add, remove, or adjust quantities as needed. Check AC Only for items that exist only in air-conditioned rooms.
  3. Click 🌱 Seed All Rooms. The system creates inventory records for every room × every template item. Already-existing records are not duplicated — safe to run multiple times.
  4. Go to the 📦 Items tab to review, set conditions, and add serial numbers or brand info.
▾ Adding & Editing Items
  1. Click + Add Item in the Items tab, or + Add Missing Item from the By Location tab.
  2. Fill in: Name, Category, Location, Condition (Good / Fair / Poor / Damaged / Missing), Description, Serial No., Brand, Purchase Date, and Purchase Price.
  3. For supply items (toilet paper, bulbs), check Is Consumable and set a Reorder At quantity. When stock falls to or below this level, the item is counted in the "Low Stock" stat on the main menu card.
  4. To flag the item for repair, check Flag for Maintenance and add notes. The item will appear in the Maintenance Flags tab.
  5. The modal shows a live Code 39 barcode preview of the item's ID.
▾ By Location Tab

Select any location from the dropdown to see:

  • Present Items — all items currently recorded at that location, with condition badges
  • Missing Items (student rooms only) — items in the template that are not found at this location, each with a one-click + Add button to create the record instantly
💡This tab is ideal for room walkthrough inspections — go room by room, check what's present, and add missing records on the spot without switching tabs.
▾ Printing Barcode Labels
  1. Go to the 🏷️ Labels tab.
  2. Use the location/category filter to narrow down items if needed.
  3. Check the boxes next to the items you want labels for, or click Select All.
  4. Click 🖨️ Print Selected Labels. A new window opens with an A4 label sheet — 3 columns, approximately 18 labels per page.
  5. Print on label paper or plain paper, cut, and attach labels to each physical item.
ℹ️Each label shows the Code 39 barcode, the item name in bold, location, and the ID in monospace. Scannable with any standard USB barcode scanner — the scanner types the ID as keyboard input.
▾ Maintenance Flags

Items with the Flag for Maintenance checkbox checked appear in the 🔧 Maintenance Flags tab.

  • Push to Maintenance — Creates a Plant Service request stub in the Maintenance module. Urgency is High for Damaged/Missing items, Normal for others. The item is marked as "pushed" so it won't be counted in the menu stat again.
  • Mark Resolved — Clears the maintenance flag and the "pushed" marker. The item returns to normal tracking.

The main menu Inventory card shows a N needs repair pill for items flagged but not yet pushed to Maintenance.

▾ Settings Tab
  • Room Template Editor — Add, remove, or adjust the standard item list for student rooms. Used by "Seed All Rooms" and the By Location missing-items comparison.
  • Category Manager — Add or remove item categories (default: Furniture, Appliances, Fixtures, Electronics, Security, Bathroom, Safety, Supplies, Office).
  • Custom Locations — Add non-standard locations (e.g., "Prayer Room", "Rooftop") that don't appear in the default common areas list.
  • 🌱 Seed All Rooms — Creates template items for all rooms from Room Reservations data.

▾ Browser & Storage Notes
  • Use Google Chrome or Microsoft Edge for best compatibility.
  • Do not use Private / Incognito mode — localStorage does not persist after the window closes.
  • Do not click "Clear browsing data → Cached images and files" or "Site data" without exporting a backup first. This permanently deletes all system data.
  • The auto-save indicator in Room Reservations shows how much localStorage is currently in use.
  • A warning appears when localStorage exceeds 3,500 KB. If you see this, check Student Profiles for large photos — crop or resize them before uploading (aim for under 500×700 px).
⚠️Student profile photos are stored in the browser's IndexedDB (not localStorage). They are included in the Export All Data backup and restored correctly. Do not rely on the browser alone — keep regular JSON backups on an external drive.

About This Project
DormPortalUniversal v4
▾ Why This Was Built

This system grew out of a practical problem: dormitory administration at Asia-Pacific International University (APIU) relied on paper forms, spreadsheets shared over USB drives, and verbal handoffs between dorm deans. Student room assignments, clearance processing, key tracking, storage rentals, and utility billing were handled through disconnected tools — each with its own file, its own format, and its own risk of data loss.

The goal was to consolidate every operational task into a single, self-contained system that:

  • Requires no internet connection — works fully offline on a dean's personal laptop
  • Requires no installation — open a file in a browser and start working
  • Requires no server or IT support — data lives in the browser, exported as a portable JSON backup
  • Covers the complete operational workflow from room reservation to clearance, key handover, room inspection, and asset tracking

Development began in May 2026 and proceeded module by module based on the daily operational needs of the dorm dean. Every feature added was driven by a real workflow gap identified in practice.

ℹ️This project started as a single HTML file (DormPortalUniversal v4) and evolved into a multi-module system over 19 development sessions. The architecture was deliberately kept simple — vanilla JavaScript, no frameworks, no build tools — so that any technically-minded dean can open, read, and understand the source code.
📋The Residence Hall Handbook module contains the full APIU Residence Hall Handbook in interactive form — all 50+ policies and a quick-reference fines table. Use it as a policy reference alongside this guide. For planned features derived from the handbook, see the Development Roadmap section below.
▾ Accessing via GitHub Pages

The system is published as a public GitHub repository with GitHub Pages hosting. This means:

  • Any dean at APIU with the link can open the app directly in their browser — no download, no installation
  • The URL follows the pattern: https://<username>.github.io/<repository-name>/
  • Each dean who opens the link gets their own completely separate and private copy of the data — data is stored in their own browser's localStorage and IndexedDB and is never uploaded anywhere
  • Opening the same link on a different computer, different browser, or in private/incognito mode starts with a fresh empty system
💡Sharing the link: Simply copy the GitHub Pages URL and send it to another dean via WhatsApp, email, or any messaging platform. They click it, enter their name, select their dorm, and start using it immediately.
⚠️Data does not sync between deans. Each dean's data is isolated in their own browser. If Elijah Hall and Esther Hall deans both open the same link, they each have a separate, independent database. This is by design — each dorm manages its own records.

To back up data and move it to another computer:

  1. On the current computer, click 💾 Export All Data on the menu page.
  2. Save the downloaded .json file to a USB drive or cloud storage (Google Drive, OneDrive).
  3. On the new computer, open the GitHub Pages link, then click 📂 Restore Backup and select the .json file.
▾ Requesting Future Updates

The system is designed to grow with the needs of the dorm dean. Two remaining modules — Staff Scheduling and Maintenance — are planned. Additional features or workflow improvements can be requested at any time.

How the update cycle works:

  1. Dean identifies a workflow gap or improvement need and communicates it to the developer.
  2. Developer implements the change and pushes the updated files to GitHub.
  3. Within 1–2 minutes, GitHub Pages automatically rebuilds and publishes the new version.
  4. All deans who open (or refresh) the link get the latest version immediately — no action required on their part.
ℹ️Backward compatibility: All updates are designed to be backward compatible. Your existing backup .json files can always be restored into newer versions of the system — new fields are automatically filled in with safe defaults when restoring an older backup.
💡If a dean on an older bookmark sees unexpected behaviour after an update, a simple hard refresh (Ctrl+Shift+R) clears the browser cache and loads the latest version.

▾ Data Privacy

All student and operational data entered into this system is:

  • Stored locally only — in the user's own browser (localStorage and IndexedDB). No data is transmitted to any server, cloud service, or third party.
  • Never uploaded to GitHub — the .gitignore file explicitly excludes all .json and .xlsx data export files from the repository. Only the application source code is published.
