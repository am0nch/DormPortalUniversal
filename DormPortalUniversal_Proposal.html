Executive Summary DormPortalUniversal v4
Overview

What We Built and Why

Elijah Hall dormitory administration has historically depended on a collection of disconnected Excel files, handwritten logbooks, and manual paper processes. Student data existed in silos — a name in a room assignment sheet, a different name in a bedding ledger, yet another in a curfew notebook — with no cross-reference, no search, and no audit trail. When the Dean needed to answer "Who is in Room 312 and when do they leave?", it required consulting multiple sources. When a curfew violation occurred, creating an incident record, linking it to the student, and exporting it for SARRA2 took hours instead of minutes.

DormPortalUniversal v4 solves this. It is a purpose-built, fully integrated dormitory management platform developed specifically for APIU's Elijah Hall operations. It runs entirely in a web browser — no server installation, no monthly subscriptions, no internet connection required during use. Every module is connected through a shared data layer, so a student entered in Room Reservations automatically appears in Student Profiles, Attendance, Incident Reports, and Clearance workflows.

Technical Architecture DormPortalUniversal v4
How It Works

Zero-Cost, Offline-First Architecture

DormPortalUniversal is built on vanilla web technologies (HTML, CSS, JavaScript ES6+) with no frameworks, no server, no database, and no cloud subscription. It runs in any modern web browser on Windows, macOS, or iPad — no installation required.

Concern How It Is Handled Cost
Data storage Browser localStorage (text data) + IndexedDB (photos). All data stays on the Dean's device. Free
Backup / restore "Export All Data" creates a single JSON file. "Restore Backup" reloads it. One click each way. Free
Excel compatibility SheetJS library bundled inline (no CDN). Open/save .xlsx files from Room Reservations, Utilities, Student Profiles. Free (open-source)
Multi-tab sync BroadcastChannel API keeps all open browser tabs in sync in real time — change data in one tab, all others update instantly. Free (browser built-in)
Internet access Not required during normal operation. GitHub Pages hosts a public copy for initial load (optional). Free (GitHub Pages)
Security No login server to breach. Data never leaves the Dean's device. No personal data transmitted to any third-party. —
Updates New features pushed to GitHub repository. Dean pulls the latest version by refreshing the page (or downloading a new copy). Free

SARRA2 Integration Protocol

DormPortalUniversal is designed as the dormitory operations layer. SARRA2 remains the campus student affairs layer. Data flows one direction — DormPortalUniversal generates structured CSV exports; SARRA2 operators import them manually. No API coupling is needed.

Data Type Direction Method DormPortalUniversal Module
Citizenship point deductions (incidents) Dorm → SARRA2 CSV export, one click per incident or bulk by date range Incident Reports
Approved campus leave list SARRA2 → Dorm CSV import snapshot; auto-marks "On Leave" status in nightly roll Nightly Attendance
SWP worker assignment Cross-reference only SARRA2 ID field stored; hours/credits tracked in SARRA2 Dorm Workers
Privacy note: The SARRA2 CSV export contains only: StudentID, Name, Room, IncidentDate, Type, Severity, PointsDeducted, FineSuggested, Notes. No medical, financial, or sensitive personal data is included.

Shared Semester Registry (New in June 2026)

A central semester registry (Set Current Semester button in the system header) propagates the active semester to all 16 modules simultaneously. Previously, the Dean typed the semester label separately in 7 different Settings tabs — a typo caused records to miss filters. Now it is entered once.

The Dormitory Administration Office respectfully submits this proposal to Student Administration and requests formal endorsement of DormPortalUniversal v4 as the official digital records and operations platform for Elijah Hall.

This proposal requests endorsement of the following:

1. Official Recognition — DormPortalUniversal is designated as the authorized digital records system for Elijah Hall dormitory operations, replacing fragmented spreadsheet-based processes.

3. Clearance Record Validity — Digital clearance records generated by DormPortalUniversal (printable A4 / exportable JSON) are accepted as satisfying the institutional clearance documentation requirement.

4. Data Retention Policy — The local-storage model (data maintained on the Dean's device with exportable JSON backups) is acknowledged as compliant with APIU's internal data retention expectations for dormitory records.
Note on Data Privacy: All student data remains on the Dormitory Dean's laptop. No student information is stored in any cloud service, third-party platform, or external server. The system has no login screen, no network calls, and no data transmission of any kind during normal operation. Backups are JSON files stored and managed entirely by the Dorm Dean.
